# 旧版本地优先答题与云端同步设计

本文记录旧版练习同步原型：客户端判题，云端保存和恢复。该原型的接口见[旧版合同](sync-api.md)；当前 Kotlin API 合同见[聚合合同](contracts/openapi.yaml)。

## 职责

客户端获取固定版本题包，持久保存答案、首次确认、标记、位置和待同步批次；本地计算结果。个人自测本地计时，到时冻结答案，断网完成后允许补传。

云端检查身份、题目和选项归属、格式、操作序号、写入权、结果内部一致性。云端不比较标准答案；成绩保存来源 CLIENT_REPORTED。客户端加密降低明文暴露，不保证成绩真实性。

## 数据链路

```mermaid
flowchart LR
  A[客户端 AES-GCM 本地状态] --> B[按时间／数量／阶段合批]
  B --> C[接入事务保存 sync_batch]
  C --> D[持久投递器]
  D --> E[RabbitMQ]
  E --> F[按场次连续序号应用]
  F --> G[云端 JSONB 快照与应用水位]
  G --> H[接管恢复／最终结果]
```

每批一次短接收事务，后台按最多8个同场批次归组，以一个应用事务更新云端快照和处理水位。不会逐题调用数据库；批次处理状态按批更新。接收表即持久待投递来源，投递确认后记录 publishedAt，未应用记录10秒后可重新通知。数据库事务提交成功再确认 RabbitMQ 消费。

接收积压达到10000个批次时拒绝新增批次并返回503；客户端保留记录，避免无限占用磁盘。消费者有限并发与prefetch，瞬时通知重投不重复应用。

## 同步策略

普通练习有变化时30秒或10题上传，暂停／退出／换端／完成立即尝试同步。模拟器的时间触发在 watch 交互模式运行；一次性命令保存并执行满足数量阈值的同步。无变化不上传。

本地记录包含用户、设备、题包、答案、变化、待同步批次、两个水位和完成意图。加密状态使用独立随机IV、认证标签和环境密钥；写临时文件、fsync、原子替换。CLI设备进程锁防同设备并发；陈旧锁在确认原进程不存在后清理。

形成不可变上传批次时分配连续seq，HTTP失败重复发送原batchId。接收后保留本地批次，直到应用水位覆盖它才清理。网络恢复后补传，旧设备epoch被撤销时保留冲突数据并停止自动覆盖。

## 一致性

practice_session 保存归属、题包、控制状态、writerId/epoch、接收水位、屏障及最终结果。sync_progress 保存应用水位和快照。sync_batch 保存不可变操作及投递／处理凭据。

接收锁定控制行：检查幂等→写入权→连续序号→插入批次→推进接收水位。不同用户之间不存在全局场次锁。

Worker 锁应用进度行，从数据库取最早未应用批次按序应用，RabbitMQ通知本身可乱序。事务失败不推进水位；数据库已提交但ACK失败的重投读取既有状态。确定性坏批次进入BLOCKED，状态查询显示阻塞，数据库记录错误码；不越过它应用后续记录。

快照包含答案与首次判定、标记和当前位置。TEST草稿可修改；PRACTICE首次确认之后不能修改答案、判定或得分。客户端操作采用固定题目版本，但云端只检查数据结构和分值一致性。

## 接管与完成

同一场次只允许一个写入实例。接管先设置HANDOVER并固定接收水位；已接收批次全部应用后递增epoch、开放新端。原设备不可用时只能恢复已上传部分；本地未上传数据不自动合并。

完成先确保剩余批次持久接收，再提交最终序号和客户端结果。云端设SEALED／FINISHING，等应用到屏障后验证逐题答案与快照及汇总一致，再写COMPLETED。完成结果不可修改；重复完成请求按requestId和负载摘要幂等。

本地限时与完成时间是客户端行为，云端不以接收时间拒绝迟传，不运行权威自动判题交卷。模拟器关闭期间没有后台进程计时，再启动检查时间并按已保存答案结算。

## 故障与验收

本地存储／密钥错误立即提示，不宣称保存成功。RabbitMQ不可用时保留接收表，恢复后投递；数据库不能接收时不返回202。临时数据库消费故障送入死信，由持久接收表重新投递，避免热重排队。

开发环境使用独立容器与数据卷；集成测试覆盖队列、重复、身份隔离、接管、提交前后故障注入、队列中断恢复、本地结果晚传与错误汇总。命令行场景覆盖20题、加密文件重启、断网补传和集中完成；100并发测试记录请求与时延，核对所有接收序号已应用。

生产身份、真实平台密钥管理、保留期清理和生产高可用部署尚未实现。生产备份须覆盖接收批次、应用水位、快照和结果的一致状态，不能只备份消息队列。
