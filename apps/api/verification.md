集成测试使用真实临时数据库和消息服务，覆盖重复上传／应用、批次内容冲突、用户隔离、序号与体积／选项校验、接管屏障、本地自测迟传、错误汇总、提交前后事务故障和 RabbitMQ 应用停止后恢复。自测测试刻意上报与标准答案不同的“正确”判定，确认云端按 CLIENT_REPORTED 保存。

重启脚本在 test 配置的两个提交边界调用 Runtime.halt，退出码分别为91和92。提交前退出后水位仍为0，提交后确认消息前退出后水位为5；重启均恢复5题并完成，未重复应用。脚本执行期间独占8082，共享专用开发数据库／队列，其他后端实例必须先停止。

客户端测试覆盖认证加密、错误密钥、用户／设备隔离、断网保存与重启、首次答案锁定、同批次重试、到时冻结、完成意图、接管保留首次判定、30秒／10题合批以及无变化不请求。CLI场景另逐题核对云端答案、首次判定、得分、标记与位置。

## 并发实测

| 指标 | 本次值 |
|---|---:|
| 客户端／题目数 | 100／2,000 |
| 答案上传请求 | 200（每10题一批） |
| 全部HTTP请求 | 1,000（含创建、状态、完成、结果与最终核对） |
| 全流程耗时 | 20.901秒 |
| 集中完成及最终核对耗时 | 4.066秒 |
| 客户端观测HTTP P95 | 6,039毫秒 |
| 数据库接收到应用 P95／最大值 | 2,068.96／2,128.89毫秒 |
| 最终状态 | 100场COMPLETED，200批APPLIED，2,000操作与2,000答案，接收／应用水位一致 |

HTTP耗时包含同一Node.js进程内100设备同步落盘阻塞事件循环的影响；它是客户端观测值。处理延迟直接从本次200批数据库 accepted_at／applied_at 计算。此测试确认已接收数据能排空，生产容量需在目标机器用独立负载进程和真实题量测量。

## 修改范围核对

工程、配置、测试、运行报告及说明写入均限定在 apps/api/；当前分支与提交历史保持原样。目录外18,170个条目的清单、文件内容、权限、链接目标和Git状态进行了前后核对。

Git状态一致；其余源码、配置、文档与依赖条目一致。`.codegraph/codegraph.db`、`.codegraph/codegraph.db-shm`、`.codegraph/daemon.log` 被已经运行的CodeGraph后台监听器自动更新，日志记录 Auto-synced。它们属于目录外运行缓存，因此“目录外所有文件字节完全一致”这一验收项有此例外。没有回写或清理这些缓存，详细差异记录在 `.runtime/scope-result.json`。
