# 院级管理设计与实现说明

更新日期：2026-10-29。

本轮提供可在浏览器操作的第一版院级管理，用于继续讨论界面与交互。沿用现有 React、Arco Design、Gateway 与本地 Mock，不新增依赖。

## 业务约定

- 组织关系为：当前大学 → 学院 → 专业 → 入学年级。年级使用“2025 级”等固定入学年份，不随学生升入大二、大三自动变化。
- 学院、专业、年级共同构成学生可选的归属目录，分类可以在尚无学生时提前建立。
- 题库工作台为题库配置展示范围；答题端计划根据学生保存的三项资料匹配展示，学生修改归属后重新匹配列表，已有学习记录保留。这是展示筛选规则，不引入身份认证或资料修改审批。
- 以上展示规则更新了历史文档中仅作为推荐条件的产品约定；管理端已实现范围配置与匹配预览，学生端的对应改造尚未接入。

## 页面与交互

入口为 `/colleges`，侧栏位于运营概览之后，保留学院建筑图标。

| 选中位置 | 右侧内容 | 新增操作 |
| --- | --- | --- |
| 全部学院 | 学院名称、代码、专业数、学生人数、可选状态 | 新增学院 |
| 学院 | 当前学院的专业列表 | 新增专业，固定所属学院 |
| 专业 | 当前专业的年级列表 | 可一次勾选多个入学年份 |
| 年级 | 年份、可选状态、学生人数及只读学生列表 | 可继续新增同专业年级 |

左侧搜索覆盖学院、专业名称及代码和年级，保留命中节点的上级路径；右侧搜索与状态筛选只作用于当前列表。面包屑、名称及操作按钮均可切换层级。

新增与编辑采用弹窗。请求失败保留输入，存在未保存修改时取消需确认。学院、专业的所属关系在本版编辑时固定，暂不提供跨学院或跨专业迁移。

正常演示场景包含两个学院、三个专业，每个专业默认配置 2024、2025、2026 级。人数根据演示学生资料计算；未完善资料的学生不计入具体分类，同一个入学年份在不同专业独立维护。

## 关联保护

- 学院下有专业或学生、题库直接引用时，不能直接删除。
- 专业下有年级或学生、题库直接引用时，不能直接删除。
- 年级已有对应学生，或被适用范围中的相同专业、学院和入学年份条件引用时，不能删除或直接修改年份。
- 同一专业不能重复创建相同年级；批量新增先校验整批，再一次保存，避免只写入部分年份。
- 停用不会删除记录。上级停用时下级显示“随上级停用”，原下级启用状态保留，恢复上级后重新生效。
- 管理端的可选状态及说明为后续学生端接入提供约定；当前没有真实学生选择器或服务端权限检查。

## 本地数据与验证

继续使用 `qanda-admin-playground-v3` 存储键，持久化版本升为 2。版本 1 数据只补齐年级目录，保留题库发布状态、学生与学习记录；学生或题库已引用的旧年份会补入对应专业目录。版本 0 继续沿用原内容迁移规则。

自动化测试覆盖年级批量新增、重复及非法数据回滚、编辑、关联保护、停用保留记录、跨学院年份引用匹配、目录完整维护、版本迁移、失败写入与场景切换。

当前为本地交互原型，没有接入真实后端、数据库或学生端；页面中的学生归属只读。题库展示配置与匹配预览已在[题库工作台](admin-bank-workbench.md)实现。
