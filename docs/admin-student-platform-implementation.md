# 管理端学生平台改造说明

更新日期：2026-10-27。

本次依据[学生自主复习平台架构报告](prd/student-platform-architecture.md)，将管理端调整为学生团队维护共享复习资源的工作台。沿用 React、TypeScript、Vite、Arco Design、TanStack Query、Zustand 与现有 Gateway 边界，没有新增应用依赖。

## 1. 页面与业务调整

| 页面 | 当前行为 |
| --- | --- |
| `/dashboard` 运营概览 | 优先展示待处理纠错、缺课需求、题库草稿、缺解析和未分章情况，并提供对应操作入口 |
| `/subjects` 课程目录 | 独立创建共享课程，无须选择专业；展示题库数量及资源准备情况 |
| `/question-banks` 共享题库 | 按课程、教材关键词和发布状态筛选，进入题库工作台或编辑题库与适用范围 |
| `/question-banks/:id` 题库工作台 | 集中维护章节、题目、导入、题库说明、发布、下架、归档及学生视角预览 |
| `/questions` 全部题目 | 跨题库检索、章节筛选、编辑；支持从反馈直接打开原题编辑器 |
| `/recommendations` 适用范围 | 配置全校适用或指定推荐条件，按真实演示用户资料预览推荐结果 |
| `/feedback` 学生反馈 | 分开处理题目纠错和缺课需求，保存回复与处理状态，核对反馈时的原题 |
| `/users` 注册用户 | 查看自填院系、可选入学年份、使用情况及自选课程，停用或恢复异常账号 |
| `/colleges`、`/majors` 院系分类 | 维护分类目录，展示推荐条件引用；保留用户资料与内容引用保护 |
| 统计、公告及系统页面 | 保留原有能力，导航按内容、反馈运营、分类、系统职责重新分组 |

原 `/permissions` 链接重定向到 `/recommendations`。旧的学院逐级授权、个人课程屏蔽及管理员创建学生的管理流程已移除。

## 2. 推荐与学生自主选择

- 适用范围保存在题库上，是当前推荐事实来源。
- 全校适用不自动加入个人课程；指定范围支持多行条件，行内同时匹配、行间满足任一行即可。
- 每行至少填写学院、专业或入学年份中的一项；专业与学院须一致，年份须有效。
- 用户缺少某项资料时，不匹配依赖该资料的条件；仍可获得全校适用题库推荐。
- 仅课程启用、题库已发布且有启用题目的内容进入推荐预览。
- 未命中推荐不产生访问禁令。后台不修改学生自选课程；用户停用、推荐范围与个人选择分别处理。

正常演示场景提供未填写院系的用户，以及英语专业学生自主选择高等数学的例子，便于核对规则。

## 3. 章节与内容维护

章节采用一层结构，支持新增、改名、上下排序。全部题目与未分章始终有入口；编辑题目时可调整章节。章节归属必须与题目所属题库一致，包含题目的章节不能直接删除。

导入保留原有多文件识别、预览、顺序调整和整批校验；可将本次题目统一归入所选章节。JSON 题目可携带当前题库已有的 `chapterId`，未指定则保留未分章。跨题库章节或无效题目会阻止整批写入，错误中包含题号。

新题库始终为草稿，发布前检查：

1. 所属课程启用、推荐范围有效。
2. 至少有一道启用题目。
3. 启用题目的题型、答案、选项及章节归属有效。
4. 启用题目均有解析，题库有使用说明。

草稿允许先保存缺解析题目；已发布题库的新增、编辑和导入不能让启用题目缺少解析。下架、归档保留题目及现有关联，退出推荐预览。

题库工作台的桌面布局采用左侧章节、右侧题目。将低频操作收进“更多”，为题干、章节和状态保留空间；小屏下章节区转为顶部，表格在自身区域滚动，取消固定列以免遮挡题干，抽屉宽度受视口约束。

## 4. 反馈处理

题目纠错保留提交时的题干、选项、答案、解析和题目版本，可从处理抽屉跳转当前原题。修改题干、选项、答案或解析时递增题目版本；状态开关不改变内容版本。

题目反馈使用待处理、处理中、已解决、无需修改；缺课需求使用待评估、整理中、已补充、暂不收录。结束处理前必须填写回复，保留原始提交内容与原题快照。处理操作写入本地操作日志。

当前版本标记和快照用于管理端内容维护；真实练习的版本固定、历史成绩和学生端查看回复尚需后端及学生端接入。

## 5. 兼容旧演示数据

继续使用 `qanda-admin-playground-v3` 存储键，通过持久化版本迁移补齐字段。

- 保留原有课程、题库、题目、用户、公告及其他记录。
- 原有题库转为草稿，教材、负责人等信息允许逐步补全。
- 原课程的专业关联仅作为题库范围的初始候选，需由负责人检查。
- 原题目保留未分章状态，按需要逐步整理。
- 不把旧管理员添加、屏蔽记录转换成学生本人选择。
- 切换 Playground 场景仍会恢复对应演示数据，这是场景切换本身的行为。

`Subject.majorIds` 暂保留兼容，新的课程创建填写空列表，日常推荐不依赖该字段。后续统一 HTTP 契约时再决定移除时机。

## 6. 验证

自动化测试覆盖课程独立创建、推荐匹配与访问分离、空资料、范围校验、章节归属与排序、导入回滚、发布检查、已发布内容校验、版本与反馈快照、回复校验、引用保护、旧数据升级，以及原有公告、账号安全与异常场景。

2026-10-27 最终验证结果：

- 28 项 Vitest 测试全部通过；TypeScript 检查与 Vite 生产构建通过。
- 浏览器检查 14 个管理页面加载、桌面布局与素材渲染，未出现页面运行时异常。
- 课程独立创建、题库草稿、章节创建与归入章节导入、检查发布、学生视角预览通过。
- 学院、专业、入学年份组合条件可保存；切换全校适用会清理细分条件；未完善资料的用户可获得公共内容推荐。
- 用户详情可查看跨专业自选课程；纠错可跳转原题编辑器，回复与处理状态可保存；手机端缺课需求处理通过。
- 无效文件阻止确认，写入失败保留原记录和表单；空数据、请求失败、慢请求与千题场景通过。
- 390px 宽度下六个核心页面无整页横向溢出，手机导航、推荐条件表单及抽屉宽度通过；表格固定列不会遮住题干。
- 千题场景保留被反馈引用的原题；快速切换场景再返回原场景时，旧写请求失效，避免污染重置后的演示数据。
- 构建仍有共享 JavaScript 包约 584 kB、超过 500 kB 的提示，不阻塞产物生成；未进行生产并发压测。

## 7. 实际边界

此次交付覆盖管理端前端和本地 Mock。后端的当前架构、合同和验证入口见[后端 README](../apps/api/README.md)。管理端仍使用本地 Mock，小程序题库和练习数据仍保存在本地，客户端业务联调尚未完成。

“学生视角预览”是管理端的内容检查界面。用户自选课程及学生反馈当前使用演示记录，正式数据写入需要客户端接入 API。用户 Web 的实现目录已移除，产品范围保留在 Web MVP PRD。
