核对日期：2026-10-31。应用与接口合同版本为 `1.0.0`。路由使用微信原生 API，共享资源使用 `mobx-miniprogram@6.12.3` 和 `mobx-miniprogram-bindings@7.0.1`。锁定版本及 npm 构建入口见 `apps/miniapp/package.json`。

## 状态和请求规则

Repository 的 `resource-cache.js` 按用户、资源、查询参数和页码保存状态；`remote-data-repository.js` 负责请求及资源更新。ViewModel 将共享状态投影成展示字段，Page 使用官方绑定合并更新。练习答案、修订快照和待同步草稿继续由现有业务层持有。

| 资源 | 有效期 | 失效来源 |
| --- | --- | --- |
| 科目、题库、单题正文 | 5 分钟 | 目录刷新；练习结果更新相关进度 |
| 账号资料 | 5 分钟 | 修改资料、切换账号 |
| 学习概览、最近练习、统计、错题和收藏 | 30 秒 | 收藏、交卷、自评等学习写操作 |
| 公告各页 | 60 秒 | 主动刷新、切换账号 |
| 院校选项 | 24 小时 | 主动刷新、切换账号 |

- 同一个资源读取共用在途 Promise；有效缓存返回时零重复请求。读取失败保留已有数据，并提供区域错误提示。
- 失效后递增资源修订，旧请求即使随后返回也不能覆盖新数据。账号切换清空共享展示状态、取消旧读取，旧账号的迟到响应不能写入新账号。
- 本机学习概览和资料缓存按账号保存，格式版本为 1。练习草稿仍使用原用户的独立存储和格式规则。
- 全局业务并发上限 4，后台草稿冲刷最多占 1 个槽位；有空槽位时先发送前台请求。已发送写请求保持顺序、内容和幂等键。
- 搜索输入分别按首页 300 ms、题库 250 ms 合并。失效搜索结果被忽略；目录加载失败重试当前页，成功后才继续后续分页。
- `onShow` 恢复官方绑定，`onHide` 和 `onUnload` 销毁绑定。隐藏期间停止共享状态订阅，卸载后拒绝页面更新。
- 页面进入和路由点击没有固定等待；区域请求显示本区域状态。收藏按钮和交卷分别显示保存、提交状态。

## 游客与本机试答

游客目录、搜索和单题只读取已发布且启用的内容；管理信息和个人记录沿用认证。题目列表不显示答案，已下载试答的判题数据留在业务层。普通练习、背题、模拟考试共用两次额度；已开始练习退出后保留记录与已用次数。下载超时、失败或存储失败均不进入答题、不扣次数。

`qandaTrialPractice` 使用格式版本 1，在一次本机写入中保存快照及累计记录。恢复、回看、交卷和简答自评复用答题模型，离线完成；服务端快照接口只读取题库。账号切换保留该记录，清除小程序全部数据或更换设备会重新获得额度。第三次创建引导登录，登录返回原题库配置后创建正式练习；试答结果保留在本机。

## 顶部和布局编辑

四个 Tab 使用同一状态栏、胶囊尺寸计算；标题与胶囊同一行，状态栏只占位一次。首页蓝色渐变覆盖状态栏，题库、复盘和“我的”使用白色页头与白色状态栏；页面 JSON 同时声明首帧底色。首页右上角由微信绘制原生胶囊，项目没有叠加白底，公开 API 没有单独关闭胶囊填充的选项。

题库左右两栏背景铺满视口，272rpx 加安全区的底栏预留放在各自滚动内容末尾，避免两栏提前结束后出现横向白块。复盘使用白色页面背景，范围选择、热力图和趋势图使用浅色容器。

二级及更深页面统一使用白色页面、导航和窗口底色。错题与收藏的统计卡、筛选项和题目卡使用浅灰底，保留内容层次。游客复盘的标题与内容一起模糊，加深遮罩从状态栏背景覆盖至页面底部；登录提示位于底栏上方，底栏保持可用。时间、电量和右上角胶囊由微信原生层绘制，保持系统显示。

首页的“我的错题”“我的收藏”和考试倒计时入口每次点击都读取当前登录状态：游客进入登录页，已登录用户进入对应功能。公开目录与游客试答沿用各自的访问规则。

答题与布局编辑共用 `templates/practice-*.wxml` 和 `styles/practice.wxss`。题目信息、题干、作答区、答案解析、工具栏通过稳定节点的 CSS `order` 排序；导航、进度和上一题/下一题固定。编辑时各模块显示细边框，内部留出上下 20rpx、左右 22rpx 间距，正文仍沿用答题页左右对齐位置。右上角六点图标提供 88 × 88rpx 拖拽热区；正文保持滚动，恢复默认布局位于内容底部。WXS 更新拖拽位移，边缘触发自动滚动；松手保存，取消复位，存储失败回滚。解析的位置与显示许可分别处理；旧 `answerLayout` 读取为等效模块顺序。

## 原生路由和弹层

`utils/navigation.js` 统一调用 `wx.navigateTo`、`wx.switchTab` 等原生路由。一次跳转未完成时拦截重复点击，失败后释放状态并允许回退路由；旧跳转的完成回调不能释放新跳转的锁。

共享 `bottom-sheet`、答题卡及提交遮罩使用 `root-portal`。首页搜索、题库配置也由根节点承载。普通弹层层级为 10000，提交遮罩为 10010；遮罩接收点击和触摸，面板内滚动使用 `scroll-view`。底栏保持显示、随背景变暗，弹窗打开时由遮罩阻挡点击。关闭、切页及卸载统一释放弹层状态。

题库配置、首页搜索和公告内容通过 `portal-theme` 显式声明颜色变量；提交加载组件提供自身颜色默认值。`root-portal` 在 WebView 下的样式继承边界见 [Tencent TDesign 说明](https://github.com/Tencent/tdesign-miniprogram/blob/develop/packages/tdesign-uniapp/site/docs/dark-mode.md#特殊组件适配深色模式)，验收需检查主按钮、选中项、加载转圈及文字的实际颜色。

首屏内容直接呈现，移除了逐项入场延迟。点击反馈和已确认的公告喇叭动画保留。返回首页后，只要仍有公告，喇叭继续提示。

全小程序的按压反馈使用统一节奏：触摸立即开始，松手后保留 80 ms；列表行轻微改变底色，卡片、按钮、标签和图标轻微改变透明度。按压时保持位置与尺寸稳定，持续选中、表单校验和答题对错各自保留对应颜色。共享规则放在 `app.wxss`，底栏、章节行和答题卡组件维护相同的反馈方式。`preview-my.cjs` 提供静止与按压状态的并排预览。

真机尚未完成本轮复测，p50/p95 留待同一参考设备采集。建议每个场景采集 30 次，分别记录冷启动、重复进入及网络状态；点击反馈目标 100 ms 内，设置页点击到可操作 p95 目标 500 ms 内。首帧以 `onReady` 为代码时间点，可操作时间需结合真机录屏和实际点击核对。

开发者工具游客态的两次设置页采样：点击至原生路由调用为 0 ms；路由调用至 `onLoad` 为 770/709 ms，至 `onReady` 为 818/755 ms，原生完成回调为 1310/1243 ms；期间业务 HTTP 为 0。样本显示主要等待发生在页面 `onLoad` 之前，尚不能据此判断真机耗时。两次样本用于定位时间分布，未作为 p50/p95 或达标结论。
