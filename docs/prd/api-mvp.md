# QandA 后端 API 需求

## 目标

后端是学生自主复习平台的业务事实中心，可以通过 HTTP、真实 PostgreSQL、Testcontainers 和本地邮件捕获独立验收。产品流程为：注册 → 可选完善资料 → 查找或选择课程题库 → 练习 → 交卷 → 复盘 → 反馈 → 后台处理。

当前工程、合同和验证入口见[后端 README](../../apps/api/README.md)；模块职责、关系模型与统计口径见[后端架构与数据库](../backend-architecture.md)。

## 业务范围

| 模块 | 能力 |
| --- | --- |
| 账号和档案 | 邮箱与微信注册登录、找回密码、邮箱和微信绑定、资料维护、会话撤销 |
| 后台账号 | 独立管理员登录、平台与内容管理员、题库维护范围、用户处置、安全策略、操作日志 |
| 目录和内容 | 学院、专业、课程、题库、章节、四种题型、图片、整批导入、发布与下架 |
| 发现与选择 | 课程搜索、题库说明、匹配推荐、我的课程、常用题库、收藏 |
| 在线练习 | 固定题目与顺序、保存恢复、即时或统一反馈、标记、取消、服务端判题、幂等交卷 |
| 学习与统计 | 历史、最近学习、错题与收藏练习、个人和后台指标、日期趋势、组织与排名统计 |
| 反馈与运营 | 带题目修订的纠错、缺课需求、处理回复、定向和定时公告、用户活跃 |

## 主要规则

1. 学院、专业和入学年份选填，不阻止注册、课程搜索或已发布内容访问。
2. 课程与题库分开，专业匹配影响推荐。用户自行选择课程，移除选择保留学习历史。
3. 内容维护使用稳定题目 ID 和不可变修订。练习和反馈引用当时修订。
4. 单选、多选和判断由服务端自动判题；多选题需要确认；简答题由学生自评并单独统计。
5. 统一反馈模式在交卷前隐藏答案、解析和参考答案；即时反馈按单题确认结果显示。
6. 保存进度执行并发校验，重复交卷返回已有结果。创建、保存、交卷和其他写命令使用幂等键。
7. 管理员与学生登录身份隔离，内容管理员按题库分配维护权限。所有权限由后端校验。
8. 发布前完成题型、答案、章节与适用范围检查；导入整批校验和写入。
9. 历史记录、旧题修订及已发放图片的访问根据记录所有者保持一致。

## 工程与合同

后端采用 Kotlin、Spring Boot、JDK 21、Maven、MyBatis-Plus 和 PostgreSQL，按业务组织 Controller、Service、Mapper、实体和 DTO。应用和 OpenAPI 合同为 `1.0.0`，开发库使用当前完整 DDL 显式初始化。

OpenAPI 覆盖当前注册的接口及请求、响应、参数和错误。生成合同、Postman 和验收证据时使用真实运行结果。测试使用独立数据库和本地捕获邮件；官方微信和 SES 需要另有实际执行证据。

## 验收条件

- 空库可以初始化，错误外键、重复关系及历史事实修改被阻止。
- 无院系注册、推荐匹配、跨专业访问和内容发布过滤符合规则。
- 学生、平台管理员、内容管理员的操作范围与会话失效正确。
- 四类题目、导入回滚、题目更新和原题快照一致。
- 并发保存产生冲突，并发交卷只产生一个结果。
- 反馈回复、公告受众及日期、错题收藏和统计口径能由真实记录验证。
- 后端完成独立 HTTP 闭环；客户端联调作为后续接入工作执行。
